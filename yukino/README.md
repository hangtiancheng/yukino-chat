# yukino (Go port)

This directory is the **Go port** of the TypeScript library `@yukino.js/yukino` (reference repository `yukino-code/apps/yukino`, library-mode entry point `src/index.ts`), embedded into the chat server through `internal/bridge` (the browser-facing websocket transport lives in `internal/ws` and wraps the bridge).

The porting scope follows the TS **library graph**: every terminal-independent module reachable from the `src/index.ts` barrel. The terminal layer (`src/main.tsx`, `src/ui/**`) and the standalone browser bundle (`src/remote/fe`) are out of scope.

Status below was established by the **sixth parity pass (2026-09-21)**: five parallel deep dives covering the entire "Still open after the fifth pass" list (tools; memory+permissions; commands+hooks+session+teams; skills+worktree; llm) plus a lead integration round that handled the agent/subagent/permission-plumbing cluster directly. Earlier-pass records were treated as untrusted input and proved stale in one place: the fifth pass claimed the background-task runner context was detached with `context.WithoutCancel`, but the code never had it — the sixth pass implements it. Backward compatibility stayed explicitly out of scope, which is why several exported APIs changed shape again (`OnPermissionRequest` widened, `AgentTool.ParentChecker` removed, `AppendProjectRule`/`writeIndex`/`clearDir`/`LoadAll` now return errors).

The sixth pass resolved every item of the fifth pass's open list and, where a residual could not be resolved (host-boundary error tolerance, OS readdir order, deep WHATWG URL host validation), re-verified it and re-recorded it below. Where TS alignment had forced duplicated code, the port was consolidated Go-style (`utils.RatFixed1`, `utils.JSNumberString`). Everything here was re-verified against the current TypeScript sources, with Node/undici/glob@13 runtime behavior captured empirically where the TS source alone was ambiguous. Items marked **Residual**, and the list under "Still open after the sixth pass", are known differences that were consciously left in place rather than overlooked.

## Capability gaps that cannot be migrated

Capabilities whose TS implementation depends on an external dependency with **no equivalent in the Go ecosystem**. They are deliberately **not migrated**; recorded here so the divergence is explicit rather than accidental.

1. **`@anthropic-ai/sandbox-runtime` (isolation sandbox backend) — not migrated.**
   The TS sandbox has three implementations: `bwrap` (Linux), `seatbelt` (macOS) and `sandbox-runtime` (Node bindings to Anthropic's official container runtime). No Go module provides the sandbox-runtime semantics, so Go implements only the first two natively. Consequences, stated plainly:
   - `sandbox.backend: sandbox-runtime` is accepted by config validation (a shared config file still parses) but is **never activated**: the host wires the backend only when it is `native`; with `sandbox-runtime` the session stays unsandboxed, like `sandbox.enabled: false`.
   - The `PreparedCommand` interface lacks TS's `env`, `annotateStderr` and `cleanup` fields. Re-verified in the fourth pass that these fields are consumed **only** by the sandbox-runtime backend — both native TS backends ignore the execution context — so nothing the native backends do is lost.
   - When `native` is configured but the binary (`bwrap`/`sandbox-exec`) is missing, Bash fails closed rather than degrading to unsandboxed execution.
2. **`sharp` — no direct equivalent.** `images` uses the standard library plus `golang.org/x/image/webp` (decode only). Known differences: box-halving instead of aspect-preserving resize, no PNG palette quantization, JPEG alpha discarded rather than composited, WebP decode-only.
3. **`turndown` / `marked` — no direct equivalent.** WebFetch's HTML→Markdown converter is self-implemented on `x/net/html`; complex layouts lose fidelity and headings are always ATX.
4. **`pino` — replaced by `log/slog`.** JSONL persistence, naming and 30-day retention preserved; level strings, error serialization without stack, and Go-side sensitive-field redaction differ.
5. **`zod` / `js-yaml` — replaced by structs plus manual validation and `yaml.v3`.** Rejection semantics are aligned where it matters: the `z.coerce.number()` behavior for provider numeric fields is now a complete ECMA-262 `StringToNumber` port (hex/binary/octal literals, `Infinity`, `1e999`, JS whitespace), and zod's optional-but-not-nullable rule is applied to the provider, sandbox, mcp_servers and hooks sections. Remaining tolerance edges: parser-level error *wordings* differ (Go phrases instead of zod issue dumps); UsageTracker's persisted scores are not zod-coerced; js-yaml resolves `yes`/`no` as strings while yaml.v3 (YAML 1.1) resolves them as booleans.
6. **`glob` / `minimatch` — ported explicitly via `tools/go_glob`** with SkipDirs matching TS; residual risk is limited to edge-case combinations (symlink roots, mtime tie-breaks, walk order).
7. **OTel exporter matrix** — the Go SDK's http exporter for logs/metrics has no JSON encoding, so `http/json` falls back to protobuf.
8. **`@agentclientprotocol/sdk` (`Acp`) — not ported** (no official Go ACP SDK; the host uses its own WebSocket protocol).
9. **`@langfuse/*` SDKs — no Go SDK.** Telemetry speaks OTLP directly with hand-built attributes aligned to the TS SDK's exact output (verified against the dist sources in the fourth pass); residuals listed in the Telemetry row.
10. **`ComputerUse` in the multi-user host — not exposed.** The tool is implemented (darwin-only; TS also has win32 PWSH and linux xdotool paths) and its OpenAI Responses protocol mapping is ported, but the chat host is a shared process and the tool drives the host's screen, so it is deliberately absent from the session registry. Sub-agents also strip it.
11. **JS `String(undefined)`** — Go's nil cannot distinguish JSON null from a missing key, so `AsString(nil)` returns `"null"`; the `"undefined"` rendering of TS's optional-field call sites is not representable.
12. **Go SDK JSON key ordering** — the Stainless Go SDKs marshal request payloads with **lexicographically sorted object keys** (`internal/apijson/encoder.go` sorts both struct fields and map entries), while the TS SDKs preserve the literal insertion order of the objects they are given. Every request body is therefore semantically identical JSON whose key order differs (tool schemas, messages, tools arrays, `defer_loading` placement). Reproducing TS order would mean bypassing both SDKs with hand-written HTTP, so it is documented rather than fixed. The same difference makes tool-schema *property* order non-reproducible on the wire; ToolSearch's text output preserves the TS literal order for the top-level schema keys because that renderer is hand-written.
13. **RE2 vs JS regex** — Grep rewrites `\w/\W/\d/\D` to Unicode property escapes, but `\b/\B` remain ASCII boundaries (JS lookaround rewrites are unportable), JS identity escapes (`\q`) are rejected, and the `u`-mode fallback has no analogue.

Resolved since earlier passes (kept for traceability): **Sentry** ported via `github.com/getsentry/sentry-go`; the **context-window fetch/mapping layers** removed for TS 1M-default semantics; the **13-entry dangerous-command blocklist** emptied to match TS's deliberately empty `DANGEROUS_PATTERNS` (user decision); the **`z.coerce.number()` quoted-numeric config edge** closed via custom unmarshaling.

2. **openai-go SDK lag**: v1.12.0 models `function_call_output.output` as a plain string and `computer_call` with the older singular `action` field; the Go port injects both through the SDK's `SetExtraFields`/raw-JSON extension points so the wire format matches TS (injection points commented in `llm/openai.go`).
3. **`version`**: TS injects `__YUKINO_VERSION__` at build time with a package.json fallback; Go uses `-ldflags -X .../version.Version`, defaulting to `0.0.0-dev`.
4. **Team file location is configurable** (Go extension `concurrent` in config.yaml, default `false`): `false` uses the TS location `~/.yukino/teams`; `true` (multi-user chat-server mode) keeps team state inside the per-session workspace `<wd>/teams` so concurrent users cannot see each other's teams. The memory recall user-dir exclusion remains unconditional for the same isolation reason.
5. **Sentry lifecycle**: sentry-go has no `Close`; shutdown and flush both drain the transport with the shared 2s timeout (TS: `flush(2000)` / `close(2000)`).
6a. **Extractor/consolidator lifetime**: the TS remote host constructs a fresh `MemoryExtractor`/`MemoryConsolidator` per loop completion, so the class-level `inProgress`/throttle state never spans calls; the Go bridge keeps one `Extractor` per session (the class semantics, not the host's usage). The consolidation package still has no production caller in the Go host.
6. **ComputerUse**: darwin-only; Swift snippets run interpretively via `swift <file>`; screenshots use the Go image pipeline. The OpenAI Responses protocol mapping (computer_call / computer_call_output / safety checks) is ported.
7. **Unit of measure**: UTF-16 code-unit semantics are emulated (`utils.UTF16Len`/`TruncateUTF16`) for tool-result budgets, WebFetch, session labels, file-history summaries, skills, teammate names, permission descriptions and compaction estimation. Go cuts never split a character, which avoids the TS surrogate-split defect (third-pass audit §11.7).
8. **Map ordering**: Go maps have no insertion order. The fifth pass extended the explicit-order treatment to `file_history` (rewind/tracked order), `teams` (persisted `config.json` member order) and the usage/plan-file surfaces; the sixth pass added `commands` (registry `Complete()` order + TS registration sequence) and the UsageTracker's first-use save order. Everywhere TS iterates a Map and the order is observable, the port reproduces it explicitly (registry schemas, task lists, team/member listings, MCP config order, deferred-name UTF-16 sort). The surfaces that cannot be reproduced: model-given object key order inside tool arguments (JSON-decoded into maps — affects SyntheticOutput echo, summarizer text and the hooks HTTP body only), MCP tool schema property key order in ToolSearch output, and OS `readdir` order (Go's `os.ReadDir` sorts — memory/skills/subagent directory scans).
9. **Documented TS defects not replicated** (Go keeps the corrected behavior): team plan-approval `receiveSync` marks only the matching message read instead of dropping all others; `readPlanForReview` reads the member's effective workDir instead of the team workDir for worktree-isolated members; both TS hosts pass an empty-string `model` through `??`, so a subagent definition's `model` never actually applies through the Agent tool (`"" ?? x` keeps `""`) — Go applies the documented precedence (call-level override > definition model > parent) instead; worktree ENOENT existence probes are not logged (TS emits ~6 error lines per healthy creation).
10. **Host-boundary error tolerance** (sixth pass, deliberate): the library propagates filesystem errors up to its boundary exactly like TS throws, but at the multi-user host boundary — session-creation memory load (`GetMemories`/`BuildSystemReminder`/`LoadAutoMemoryPrompt`), session resume/save (`LoadSession`/`SaveMessage`), UsageTracker construction — Go logs the `… operation failed` error and proceeds instead of failing the whole session. In TS the same throw aborts `createRemoteAgent`/the command handler; on a shared server a transient FS error should not kill a user's chat.

## Still open after the sixth pass

The sixth pass closed every item of the fifth pass's open list. What remains are verified differences that were consciously left in place — they are recorded so the next round can pick them up rather than rediscover them. Most fall into four structural classes: Go map/readdir ordering, JSON key order through Go maps or the Stainless Go SDKs, host-boundary error tolerance (Semantic differences #10), and zod/JS runtime fidelity edges that cannot be reproduced without porting the runtime.

- **OS readdir order** (Go `os.ReadDir` sorts): `memory` reminder/dedup-manifest order and same-mtime tie-breaks, `skills` catalog duplicate-name winner and listing order, `subagent` definition-loader order, `tools` grep walk order (affects the 500-cap retention set). Fixing idiomatically is impossible (needs raw `getdents`); raw syscalls were rejected.
- **JSON key order**: model-given object key order inside tool arguments (SyntheticOutput echo, summarizer text, hooks HTTP body `args`), MCP tool-schema property order in ToolSearch, and every LLM request body (Stainless Go SDKs sort keys lexicographically — Capability gaps #12).
- **Host-boundary tolerance**: `memory.GetMemories`/`BuildSystemReminder`/`LoadAutoMemoryPrompt`, `session.LoadSession`/`SaveMessage`, `commands.NewUsageTracker` and the teams runner's mailbox `Send`/`runPlanApproval` send failures log and proceed where the TS throw aborts the caller (Semantic differences #10). `memory/consolidation` also still has no production caller (the TS remote host runs `maybeRun()` after every loop completion).
- **`Tools`**: deep WHATWG host validation (IPv4-as-number, IPv6 contents, IDNA) not emulated in `jsParseURL`; fetch transport errors render undici's opaque `fetch failed`; WriteFile 0o755/0o644 vs `0o666&~umask`; RE2 dialect edges (`\b/\B` ASCII-only, identity escapes rejected); glob tie-break uses the ICU root locale vs the runtime default; `mcp_call` name sanitizer iterates runes vs UTF-16 units; AskUserQuestion validation prose vs the zod issue dump.
- **`Worktree`**: branch-existence FS probe vs TS's `git branch --list` spawn (error surfaces from `worktree add` in the pathological case); git-missing spawn failures render `Command failed:` + empty stderr vs Node's `spawn git ENOENT`; malformed URL sources propagate Go's parse error vs undici's `Failed to parse URL from …`.
- **`Subagent`**: without a host-wired `ModelResolver` the `system_prompt` override degrades to a system reminder (the chat host wires one); P4 extensions (`AdoptRunning`/`FindByName`/`name`/`mode`) remain Go-only.
- **`Teams`**: broadcast stays best-effort+log where TS aborts on first failure (fifth-pass decision); `LoadTranscript` accepts entries missing `role`; broadcast delivery count counts attempts on lock-timeout edges.
- **`Commands`**: persisted usage scores are not `Number()`-coerced; `Object.entries` integer-keys-first enumeration not reproduced; `GetRecentlyUsed(0)` returns 5 where TS yields empty (no production caller passes 0).
- **`Hooks`**: a programmatically constructed `Hook{ID:""}` cannot signal presence (only YAML decoding can).
- **`Memory`**: the extractor returns trailing-run results alongside an error where TS discards them; the in-process `Extractor` is reused per session where the TS host constructs a fresh one per loop completion.
- **`Permissions`**: the `globMatch` compile-failure branch is practically unreachable after metachar escaping (mirrors TS's defensive catch); the fallback stringifier sorts map keys for deterministic rendering.
- **`LLM`**: `makeMessage` compacts received bytes so `JSON.stringify(JSON.parse(x))` escape normalizations are not reproduced; openai-go v1.12.0 typed-model lag handled via `SetExtraFields`/raw-JSON reparse.
- **`Agent`**: `toolSchemas` recomputed per turn (deliberate long-lived-Agent adaptation).

The third-pass audit document (`cr.md`) was removed in the sixth pass — it was stale relative to the current state (several of its "still open" items and path references had been corrected by later passes); this README is the living record.
